# Windows 托盘与唤醒验证

建议在 Windows 10 / 11 x64 上验证。当前开发主机为 macOS，交叉编译不代表这些实机检查已经通过。

## 自动化检查

```powershell
go test ./...
go vet ./...
wails build
```

Windows 专属测试会创建隐藏窗口，在真实 Win32 消息循环中投递唤醒通知，验证恢复回调、过滤重复恢复通知和关闭窗口线程；不会让测试电脑进入休眠。测试也检查 Win32 结构体布局与托盘提示的 UTF-16 截断。现有 CI 的 Windows job 会执行这些测试。

## 实机检查

使用独立测试配置和本地 HTTP 服务，避免影响日常路由。

| 操作 | 预期结果 |
| --- | --- |
| 首次打开 EXE | 通知区域或折叠区域出现 LocalRoute 图标；代理未自动启动 |
| 右键 → 启动代理 | 显示处理状态，随后显示监听地址；HTTP 请求成功 |
| 端口被其他程序占用时启动 | 窗口显示失败原因，不显示成功运行 |
| 连续点击启停 | 处理中禁用重复操作，最终状态与窗口一致 |
| 关闭主窗口 | 托盘保留，HTTP 请求仍成功 |
| 单击图标或菜单“打开 LocalRoute” | 显示已有窗口，不创建第二个代理 |
| 代理运行时睡眠/休眠，再唤醒 | 新 HTTP 请求成功；旧请求可断开并由客户端重试 |
| 主动停止代理后睡眠再唤醒 | 保持停止 |
| 任务管理器重启 Windows 资源管理器 | LocalRoute 托盘图标重新出现且菜单可用 |
| 右键 → 退出 LocalRoute | 进程退出、监听端口释放、托盘图标移除 |
| 再次打开应用 | 可正常创建托盘并重新启动代理 |

如出现异常，请记录 Windows 版本、监听地址、是否使用睡眠或休眠、托盘和窗口显示的错误，以及唤醒后首次请求的结果。
